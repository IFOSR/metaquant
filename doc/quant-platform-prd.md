## 1. 产品定义

### 1.1 产品名称

量化研究与交易平台，内部代号 `Quant Research Platform`。

### 1.2 一句话定义

一个将人工/LLM/论文研究想法转化为可验证因子、可复现策略和可审计交易包的量化平台。

### 1.3 产品定位

平台不是单纯的回测工具、代码生成器或自动交易机器人，而是由以下三部分组成：

1. **研究提案层**：帮助研究员提出假设、解析论文、生成候选因子和整理证据。
2. **确定性研究内核**：负责 PIT 数据访问、Factor IR 执行、统计检验、门禁和正式回测。
3. **交易执行层**：消费通过门禁的版本化 `StrategyPackage`，执行模拟盘和实盘交易。

### 1.4 产品北极星指标

平台的最终目标是为可部署策略创造真实、可归因、可持续的交易利润。产品北极星指标定义为：

> **平台产生的成本后、风险调整、可归因增量净利润，以及该利润相对于实际占用资本和容量的回报。**

北极星指标必须在 paper/live 阶段按真实成交、手续费、滑点、冲击、融资、借券、数据和平台成本计算，不能使用样本内利润或未经成本调整的回测收益替代。

建议的业务口径：

```text
Net Economic Alpha ROI
= (策略净 P&L - 基准净 P&L - 资金/借券/平台成本)
  / 平均实际占用资本
```

必须同时展示最大回撤、尾部损失、容量、流动性、风险暴露和利润归因。单纯的绝对利润不是充分指标：高杠杆、市场 beta、不可扩展的小容量和偶然行情都不能算作平台创造的可持续价值。

研究指标不再作为北极星，而分为两类：

**利润领先指标：**

- 独立 OOS 保持率。
- 成本后边际贡献和容量。
- 研究结果可重现率。
- 论文复现准确率。
- 从研究提案到可审计报告的交付周期。

**利润与资本安全护栏：**

- 未来函数、幸存者偏差和伪发现拦截率。
- 实盘/模拟与正式回测的成交语义偏差。
- 风险限额、对账差异、订单异常和 kill switch 触发率。
- 策略发布后的净 P&L 漂移、最大回撤和失效速度。

平台早期没有真实资金时，使用 paper/shadow 的净经济 alpha 作为代理指标，并明确标注为代理，不把它当作已经实现的商业利润。

### 1.5 首阶段市场边界

第一阶段只服务中国境内两个市场域，其他市场不进入 MVP 的正式研究、回测或交易验收：

| 市场域 | MVP 范围 | 主要研究对象 | 第一阶段默认频率 |
|---|---|---|---|
| `CN_A` | 上海证券交易所、深圳证券交易所的人民币普通股；以主板和历史可追溯的主流指数成分为起点 | 个股横截面因子、行业/风格中性组合、事件和基本面因子 | 日频 |
| `CN_COMMODITY_FUTURES` | 境内商品期货交易所：上期所、能源中心、大商所、郑商所、广期所；先覆盖流动性和数据质量达标的主力品种 | 时序动量、期限结构/展期收益、基差、波动率、跨品种相对价值 | 日频；验证后再扩展 5 分钟 |

以下内容明确不在首阶段范围内：美股、港股、海外期货、股指期货和国债期货、期权、场外衍生品、现货跨市场套利以及未完成交易规则和数据验证的品种。北京证券交易所、科创板、创业板和商品期货的非主力/低流动性合约是否进入首阶段，由对应市场域的规则、数据和执行 golden set 通过后单独批准，不得因为“统一接口”而默认支持。

两个市场必须使用不同的 `MarketDefinition`、`InstrumentMaster`、`TradingRuleVersion`、`CostModel` 和 `ValidationPolicy`。统一的是研究任务、Factor IR、实验账本和策略包接口，不是交易语义。

**A 股必须建模的约束：**

- T+1 可卖、交易日历、集合竞价和连续竞价时段。
- 涨跌停、价格笼子、停牌、ST/风险警示、上市状态和退市。
- 最小交易单位、现金/持仓可用性、公司行动、复权与未复权价格。
- 印花税、佣金、过户费、滑点、冲击和无法成交订单的顺延。
- 历史指数/行业成分和证券状态，防止幸存者偏差。

**商品期货必须建模的约束：**

- 交易所、品种、合约、合约乘数、最小变动价位、报价单位和到期日。
- 日盘/夜盘交易时段、跨日交易日归属、集合竞价和交易日历。
- 涨跌停、保证金、涨跌停板调整、手续费、平今/平昨和结算规则。
- 每日盯市、结算价、可用资金、强平风险、持仓限额和交割月限制。
- 主力/次主力识别、连续合约构造、展期规则、换月成本和真实合约可交易性。
- 研究使用连续合约时，交易执行必须还原到实际合约，禁止把连续合约价格直接当作可成交价格。

**市场专属研究假设：**

- A 股优先研究价值、质量、盈利修正、动量、反转、流动性和行业/风格暴露控制；因子验证以横截面 IC、分层收益、换手和容量为主。
- 商品期货优先研究时序动量、期限结构、展期收益、基差、库存/宏观驱动和跨品种相对价值；验证以时序收益、风险调整收益、换月稳定性、保证金占用、组合相关性和极端行情表现为主。
- 跨市场组合不是首阶段默认目标。先分别跑通 A 股和商品期货的单市场研究到 paper 闭环，再评审跨资产资本配置。

## 2. 背景与问题

### 2.1 当前问题

量化研究通常存在以下问题：

- 研究员、论文代码和 Agent 各自使用不同的因子表达方式。
- 财务、成分和证券状态数据经常使用修订后数据，无法证明决策时点可得。
- 回测把收盘价、成交价、信号时间和收益时间混在一起，导致同收盘成交、未来函数和成本低估。
- 研究只保留成功结果，失败候选、重复试验和调参次数丢失，无法进行多重检验。
- LLM 可以快速生成策略代码，但生成结果难以验证、复现和审计。
- 研究回测与模拟/实盘使用不同代码和不同交易语义，导致回测结果无法迁移。
- A 股交易约束，如 T+1、涨跌停、停牌、ST、最小交易单位和印花税，容易被遗漏。
- 商品期货的合约生命周期、夜盘归属、保证金、每日结算、展期和主力合约切换容易被股票化建模，导致收益、杠杆和容量失真。

### 2.2 用户痛点

| 用户 | 主要痛点 | 期望结果 |
|---|---|---|
| 量化研究员 | 因子定义、数据口径和实验记录不统一 | 快速提出、验证和比较候选因子 |
| 策略研究员 | 因子组合和成本后表现难以复现 | 生成有约束、有归因的策略 |
| 研究负责人 | 难以审计研究过程和控制过拟合 | 查看完整证据链、审批和门禁 |
| 交易工程师 | 回测与实盘执行语义不一致 | 使用同一策略包进行回测、模拟和实盘 |
| 风控/合规人员 | 交易凭证、数据许可和审批不可追溯 | 可追踪、可撤销、可审计 |
| 平台工程师 | 数据、计算和 Agent 系统耦合 | 组件可替换、任务可重放、故障可恢复 |

## 3. 产品目标与非目标

### 3.1 产品目标

MVP 需要支持：

1. 人工或 LLM 输入研究假设、市场域和市场专属约束。
2. 输入论文/PDF，抽取公式、变量、实验设定和证据引用。
3. 将人工公式、论文公式和 Agent 输出统一编译为 Factor IR。
4. 使用 PIT 数据和时间类型检查阻断不可证明安全的因子。
5. 自动执行数据质量、预测能力、稳健性、独立性、成本和容量验证。
6. 通过门禁的因子进入 Alpha Pool，并可构建组合策略。
7. 对 `CN_A` 和 `CN_COMMODITY_FUTURES` 分别使用市场规则驱动的五时钟回测，并在商品期货增加结算时钟。
8. 输出可定位到研究假设、论文页码、数据快照、代码版本和审批记录的报告。
9. 输出不可变、版本化的 `StrategyPackage`，供独立交易执行系统消费。

### 3.2 MVP 非目标

- 不承诺自动发现可交易 alpha。
- 不在第一阶段覆盖中国境外市场、股指/国债期货、期权、数字资产、场外衍生品和跨市场事件策略。
- 不允许 LLM 直接生成并执行任意 Python、SQL、Shell 或网络请求。
- 不在第一阶段开放自动实盘发布。
- 不在第一阶段建设微服务集群、分布式 AutoML 或强化学习搜索。
- 不把任何第三方平台的回测结果直接当作正式研究结果。

## 4. 用户角色与权限

### 4.1 角色

- `Researcher`：创建研究任务、提交假设和查看个人实验。
- `StrategyResearcher`：管理因子组合、策略和回测。
- `ResearchLead`：审批预注册、门禁 waiver、Alpha Pool 晋级和策略发布。
- `ExecutionOperator`：管理 broker、paper/live 环境、订单和应急操作。
- `RiskReviewer`：查看风险、成本、容量、暴露和交易约束。
- `DataSteward`：维护数据合同、字段许可、PIT 规则和质量策略。
- `PlatformAdmin`：管理用户、资源、模型 provider、运行环境和审计。

### 4.2 权限原则

- 最小权限。
- 研究环境、paper 环境和 live 环境隔离。
- Agent 默认无交易凭证和 live 权限。
- 打开 lockbox、审批 waiver 和发布 live 策略必须双人或分离职责。
- 所有写操作必须记录 actor、reason、对象版本和父级 artifact。

## 5. 核心用户流程

### 5.1 假设驱动因子流程

```text
ResearchBrief
  -> 研究假设确认
  -> 字段和数据可行性检查
  -> 候选因子生成
  -> Factor IR 编译
  -> PIT/静态安全检查
  -> 预注册
  -> 因子计算和验证
  -> 人工晋级
  -> Alpha Pool
```

### 5.2 论文复现流程

```text
PDF + 来源 + 许可
  -> 页级解析
  -> 主张、公式和实验设定抽取
  -> 变量映射
  -> faithful reproduction
  -> local adaptation
  -> Factor IR
  -> 验证、差异分析和复现分级
  -> 报告
```

### 5.3 策略到交易流程

```text
通过门禁的 FactorVersion
  -> Alpha Pool
  -> 组合构建
  -> StrategySpec
  -> 不可变 StrategyBuildArtifact
  -> 正式回测（消费 StrategyBuildArtifact）
  -> StrategyPackage payload（引用已接受的正式回测）
  -> paper/live 独立审批 attestation
  -> shadow
  -> paper
  -> 小资金 live
```

`StrategyPackage` payload 不包含 `approved` 等可变状态；批准、拒绝、过期和撤销由绑定 package content hash 的独立 attestation 表达。

## 6. 功能需求

优先级定义：

- `P0`：MVP 必须交付。
- `P1`：第一版生产研究平台交付。
- `P2`：后续增强。

### 6.1 研究任务与提案

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| FR-001 | P0 | 创建 `ResearchJob` | 只能选择已启用的 `CN_A` 或 `CN_COMMODITY_FUTURES`，并定义频率、universe、决策/交易/结算时钟、horizon 和候选预算 |
| FR-002 | P0 | 提交 `ResearchBrief` | 支持假设、机制、预期方向、反证条件、可用数据域和约束 |

| FR-004 | P0 | 记录所有候选 | 成功、失败、重复、拒绝、超预算候选均进入试验账本 |
| FR-005 | P1 | 多 Agent 研究委员会 | 能输出支持观点、反方观点、数据风险、反证条件和综合建议 |

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| FR-601 | P1 | shadow trading | 只生成目标仓位和订单建议，不发送真实订单 |
| FR-602 | P1 | paper trading | 使用真实行情或延迟行情模拟订单和成交 |
| FR-603 | P1 | live 发布审批 | 策略包、数据合同、风险参数和审批全部齐备 |
| FR-604 | P1 | 交易安全 | 幂等键、notional cap、kill switch、MFA、对账和重启恢复 |
| FR-605 | P2 | 多 broker | 通过统一执行接口接入多个 broker |

### 6.8 Web UI 与交互

Web UI 是研究、审批和交易运维的统一工作台，不承担因子计算、门禁裁决、风险裁决或订单生成逻辑。所有页面通过版本化 Control Plane API 和事件流访问数据，并必须展示数据快照、规则版本、结果状态和权限边界。

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| FR-701 | P0 | 应用壳层和 RBAC | 支持登录、角色权限、市场域切换、全局导航、任务状态和审计入口；研究、paper、live 环境隔离 |
| FR-702 | P0 | 研究任务工作台 | 可创建 `ResearchJob`、填写 `ResearchBrief`、查看候选、预算、运行状态、失败原因和人工审批节点 |
| FR-703 | P0 | 因子和实验页面 | 可查看 Factor IR、编译错误、输入字段、时间依赖、实验参数、OOS、成本、容量和 GateDecision |
| FR-704 | P0 | 报告和 lineage 页面 | 可从结论追溯到因子版本、数据快照、规则版本、代码/容器版本、论文页码、证据和审批记录 |
| FR-705 | P1 | 策略和回测页面 | 支持 Alpha Pool、`StrategySpec`、组合约束、正式回测、归因、风险和回测对拍结果查看 |
| FR-706 | P1 | paper/live 运维页面 | 支持 shadow/paper 状态、订单、成交、持仓、P&L、风险、对账、发布审批和 kill switch；live 危险操作必须二次确认 |
| FR-707 | P0 | 完整状态反馈 | 每个长任务页面具备 loading、empty、error、permission denied、stale data、long-running、retry 和 audit 状态 |
| FR-708 | P0 | 响应式和可访问性 | P0 页面支持桌面和移动端基本访问，关键操作可键盘完成，图表具备文本摘要，颜色不是唯一状态表达方式 |

UI/UX 的交付顺序不是等待后端全部完成，而是：

```text
PRD/角色/用户流程冻结
  -> 信息架构、页面地图和 P0 原型
  -> 设计 token、组件规范和页面状态
  -> API schema/mock contract
  -> 前端应用壳层和研究页面
  -> 报告、策略和回测页面
  -> paper/live 运维页面
  -> E2E、可访问性和视觉回归
```

其中，P0 原型和页面状态必须在 Phase 0 完成；研究工作台、因子和验证页面可在后端 API 尚未完成时基于 mock contract 开发；paper/live 页面必须等待交易状态、风险和审计 API 稳定后再进行真实联调。

## 7. 产品非功能需求

### 7.1 可复现

- 相同 `run_fingerprint` 必须产生相同关键 artifact hash。
- 报告中的每个指标可定位到实验、代码、容器、依赖、数据快照和政策版本。
- 失败重跑生成新的 attempt，不覆盖旧结果。

### 7.2 可审计

- 所有提案、候选、调参、拒绝、审批、waiver 和 lockbox 操作可查询。
- 研究报告 manifest 使用内容哈希和签名。
- 审计日志只追加，不允许普通用户删除或修改。

### 7.3 性能目标

- 3,000-6,000 只 A 股、10 年日频，单个中等因子计算和基础评估 P95 小于 10 分钟。
- 50-100 个商品期货品种及其近月/主力合约、10 年日频，单个中等因子计算和基础评估 P95 小于 10 分钟。
- 20 个标准因子完整评估在目标集群小于 60 分钟。
- 任务基础设施成功率不低于 99%。
- 月度 replay 成功率不低于 99.5%。

### 7.4 安全

- Agent 无默认 live 权限。
- 外部 PDF、作者代码和第三方数据按不可信输入处理。
- 研究计算运行在无网络、非 root、只读输入和资源限额容器。
- 禁止任意 `eval`、Shell、网络请求和文件 IO 进入 Factor IR。

## 8. 产品验收标准

### MVP 必须通过

1. 3-5 个经典 A 股日频因子和 3-5 个经典商品期货日频因子可由 Factor IR 编译并重算。
2. 已知未来函数、幸存者偏差、同收盘成交和修订泄漏 100% 被测试拦截。
3. A 股历史 universe、停牌、涨跌停、ST、T+1、公司行动和交易成本具备 golden set；商品期货合约链、夜盘归属、涨跌停、保证金、结算、换月和交易成本具备独立 golden set。
4. 正式实验预注册率和候选登记率达到 100%。
5. 相同 run fingerprint 的关键结果一致。
6. 可以输出完整研究报告和可定位 lineage。
7. 通过门禁的策略可生成 StrategyPackage，但 MVP 不自动实盘发布。

### 生产研究版必须通过

- 支持论文 R0-R4 复现分级。
- 支持 Alpha Pool、组合优化、容量和风险归因。
- A 股和商品期货分别具备市场专属验证政策、回测账本、成本模型和 paper 对拍结果。
- 支持 shadow/paper、审批、kill switch、对账和回放。
- 研究平台与执行平台只通过版本化策略包交互。

## 10. 产品风险和决策

### 关键风险

- 数据供应商无法提供历史可见版本。
- 商品期货主力连续合约无法还原到实际可交易合约。
- LLM 通过提示词或工具绕过确定性门禁。
- 平台回测与 NautilusTrader 回测语义不一致。
- A 股或商品期货交易规则建模不完整。
- 过度自动化造成多重检验和过拟合。
- 第三方平台接口变化或许可证约束导致锁定。

### 强制决策

- Factor IR 是唯一正式计算入口。
- 所有研究结果必须绑定 snapshot、代码、容器、政策和依赖版本。
- LLM 不拥有正式计算、门禁、lockbox 和 live 发布权限。
- 正式回测和实盘执行独立于研究 Agent。
- 研究失败必须保留，不能只保存胜出结果。
- A 股和商品期货必须分别达到各自市场的 golden set 和 paper 对拍标准，不能用一个市场的验证结果替代另一个市场。
