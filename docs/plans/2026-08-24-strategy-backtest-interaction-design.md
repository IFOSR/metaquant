# 策略回测交互重构：交互设计

日期：2026-08-24
状态：已实施（P1/P2/P3 全部落地并测试通过）

## 0. 背景：当前交互哪里错了

现状是「策略对话 → 产物面板挂一个回测按钮 → 失败在点击后爆炸」。问题有四个：

1. **数据是事后补丁**：先点回测、炸了、再告诉用户没数据——顺序反了。
2. **选择受限于已有数据**：用户能选什么周期/时间段，取决于库里碰巧有什么。
   但 iFinD（同花顺）接口支持**任意周期、任意时间段**——限制是错的。
3. **不支持策略的真实数据需求**：策略可能是「日线看趋势 + 分钟找入场点」
   的多周期结构，当前只能跑单一周期。
4. **澄清不在对话里**：周期、时间段这些本该是 Agent 和用户对话澄清的内容，
   现在却是面板上几个没有上下文的控件。

## 1. 设计原则

1. **对话是第一界面**：周期、时间段、多周期配合，都在对话里澄清；面板是对话的
   结构化呈现与精修入口，两者收敛到同一份「回测方案」。
2. **方案先行，数据随后**：先确定「回测方案」（用什么周期、多长时间段、为什么），
   系统再据此**构建**数据——不是让用户迁就已有数据。
3. **数据跟着策略走**：Agent 从策略内容推导数据需求（趋势周期、执行周期、
   所需历史长度），给出建议并说明理由；用户可改。
4. **状态全程可见**：数据构建的每一步（每个标的 × 周期 × 时间段）都有明确状态，
   回测按钮只在数据全部就绪后可用。
5. **失败即引导**：任何失败都给出下一步动作，不留死胡同。

## 2. 全流程

```
S1 策略构思            S2 回测方案澄清          S3 数据准备          S4 回测
──────────────        ─────────────────        ─────────────       ─────────────
自然语言描述策略   →   Agent 给出方案建议    →   按方案自动构建   →   回测
「5 日均线上穿…」      （周期/时间段/理由）      数据，状态逐项       净值/指标/成交
多轮澄清需求           用户对话调整或            可见：下载中/         结果展示
                     面板直接改               就绪/失败
                     ↓
                     收敛为一份「回测方案」
```

## 3. 阶段详设

### S1 策略构思（保留现状）

左侧对话流 + 右侧「策略产物」面板（说明/代码/状态徽章）。保持不变。

### S2 回测方案澄清（核心新增）

策略就绪（ready）后，Agent 在对话中主动给出**回测方案建议**，以方案卡片呈现：

```
┌─ Agent ────────────────────────────────────────────────┐
│ 策略已就绪。这是均线趋势类策略，我的回测建议：            │
│ ・周期：日线（趋势策略不需要分钟级精度）                   │
│ ・时间段：2025-08-24 ~ 2026-08-24（近一年，覆盖一轮       │
│   完整震荡与趋势段）                                      │
│ ・标的：600000.SH                                        │
│ 想调整的话直接说，比如「拉长到两年」「加 5 分钟看入场」。   │
│                                    [采用此方案]          │
└──────────────────────────────────────────────────────────┘
```

三条调整通道，收敛到同一份方案：

- **对话调整**：「用近半年」「加 5 分钟周期看入场点位」——Agent 更新方案。
- **面板编辑**：右侧「回测方案」面板直接改周期/起止日期（结构化精修）。
- **采用建议**：点「采用此方案」一键接受 Agent 建议。

方案字段：`周期（可多选：日线/5/15/30/60 分钟）× 时间段（起止日期或快捷：
近 3 月/近半年/近 1 年/近 2 年）× 多周期角色（趋势周期/执行周期）`。

### S3 数据准备

方案确定后，系统**自动构建**所需数据（不再要求数据预先存在）：全部走
iFinD——日线用 `date_sequence`（任意起止区间），分钟线用 `high_frequency`
端点（任意分钟周期、长历史、含夜盘，契约已验证）。面板逐项显示构建状态：

```
数据准备
✅ 600000.SH · 日线 · 2025-08-24~2026-08-24 · 243 行 · 就绪
⏳ 600000.SH · 5分钟 · 2026-07-24~2026-08-24 · 下载中…
❌ AU2610.SHF · 日线 · 拉取失败（换源重试 / 让 Agent 换标的）
```

### S4 回测与结果

数据全部就绪 → 回测按钮点亮。结果区沿用现有指标卡片 + 净值曲线 + 成交/持仓。
多周期策略（P2）在结果中标注每个周期的角色。

## 4. 状态与文案

| 状态 | 视觉 | 文案 | 下一步动作 |
|---|---|---|---|
| 方案待定 | 中性卡片 | 「策略就绪后，我会给出回测方案建议」 | 等待/对话 |
| 方案建议 | 方案卡片 | 周期+时间段+理由 | [采用此方案] 或对话调整 |
| 数据下载中 | 黄点 +  spinner | 「下载中…」 | 等待 |
| 数据就绪 | 绿点 | 「243 行 · 起止日期」 | 回测可用 |
| 数据失败 | 红点 | 「拉取失败」 | [重试] [让 Agent 换标的] |
| 回测错误 | 红色面板 | 具体报错 | [让 Agent 修复此报错] |

文案原则：从用户视角命名（「数据已就绪」而非「coverage ok」），动作说明后果
（「采集所需数据」而非「provision」），失败给出明确下一步。

## 5. 布局与组件

右侧栏改为三个叠放区块：**策略产物 → 回测方案 → 数据准备**。回测按钮与结果
留在「数据准备」区块之下，形成「策略 → 方案 → 数据 → 结果」的自上而下动线，
与左栏对话流一一对应。移动端单列堆叠，顺序不变。

签名元素：**回测方案卡片**——Agent 的建议第一次以结构化、可一键采用、可对话
修改的形态出现，是「方案先行」原则的载体。
