# 研究工作台重构设计方案（Research Workbench Refactor）

**日期：** 2026-08-26
**状态：** 待评审（用户已确认交互方向，本节沉淀为落地蓝图）
**目标读者：** 产品 / 工程 / UI 设计
**上游文档：** [2026-08-24-strategy-backtest-interaction-design.md](./2026-08-24-strategy-backtest-interaction-design.md)

---

## 0. 一句话目标

把当前「研究任务 + 因子构建 + 策略对话 + 因子回测 + 策略回测 + 仿真盘」割裂且入口冗余的系统，重构为**一个统一的「研究」容器**：用户用自然语言（底层由 `pi` Agent 非交互支撑）逐步细化，得到一个因子或策略，然后 生成代码 → 代码正确性测试 → 调用 NT 回测 → 发布仿真盘；**任意步骤可保存**，全程以证据与可视化为线索。

---

## 1. 背景与现状痛点

| 痛点 | 现状 |
|---|---|
| 入口冗余、命名歧义 | 同一件事有三种叫法：导航 `新建研究`、首页 `新建研究任务`、列表页 `新建任务`，全指向 `/research/jobs/new` |
| 创建页两套机制并存 | `/research/jobs/new` 同时有 `PaperPipeline`（自然语言一键创建）与 `ResearchJobForm`（详细表单），用户不知走哪条 |
| 因子 / 策略割裂 | 因子走「研究任务 → 简报 → 因子构建 → 训练/推理/验证 → 晋升」；策略走「策略对话 → 冻结 → 回测 → 仿真盘」，两套 UI、两个回测入口、两套 payload |
| 无法带附件 | `StrategyMessageModel` 只有 `role + content`；对话不能传文本/图片，无法从研报、图表沉淀 |
| 无「代码正确性测试」 | 因子侧有 sandbox 试运行（`smokeFiles`），策略侧没有；策略只在回测时才编译+安全检查 |
| 回测展示藏在对话侧栏 | 回测结果（sparkline/指标）只在 `strategy-chat` 右侧，不是一个独立、可管理的工作台 |
| 没有「回测→发布」语义 | 只在 `FROZEN` 态露出「开仿真盘」，不绑定「哪条回测结果」→ 哪个仿真账户 |

## 2. 目标信息架构（4 项导航）

```
研究工作台
├── 概览          Overview      —— 全部研究（因子+策略统一列表）+ 阶段进度 + 计数 + 最近活动 + 待办
├── 新建研究      New Research  —— 统一 NL 工作台入口（对话+附件 → 自然产出因子或策略）
├── 回测          Backtest      —— 回测工作台：选研究 → 看建议 → 用户改周期/区间 → NT → 可视化 + 历史
└── 仿真          Simulation    —— Paper 工作台：发布研究、监控账户/成交/持仓/净值
```

- 删除导航：`研究任务`、`策略`、`策略对话`、`执行`。
- 顶部「环境」选择器保留（研究 / 仿真 / 实盘），实盘不再单独设导航；市场选择器保留（A股 / 商品期货）。

> **命名统一**（采用你的倾向）：全站叫「研究」，不再出现「任务 / 项目 / 因子任务」等混用；因子与策略都是「研究」的形态，前端不强行区分，由对话自然生成。

## 3. 统一「研究」容器与生命周期

因子和策略同为一个 `Research` 对象，差异仅在 `kind` 与 `code` 形态，由对话/产物自然判定。生命周期（**任意步骤可保存**）：

```
Research 生命周期
 ① 创建（对话 + 附件）
 ② 定稿 ready          用户确认规格（标题/说明/标的/周期/目标自动判定）
 ③ 生成代码             Agent 产码 + 静态安全扫描（已有）
 ④ 代码正确性测试       NEW：沙箱「跑通即可」（非回测）
 ⑤ 回测                 NT 引擎（原样复用）→ 可视化 + 历史入库
 ⑥ 发布仿真             回测通过 → 建/绑仿真账户 → 直播监控
      ▲
      └── 任意一步均可 【保存】 = 版本化快照（content_hash），可回滚/恢复/分享
```

- **保存是任意时刻能力**，不是终点：每次保存生成不可变快照，随时回滚。
- **研究字段**：
  - `id / owner / market`
  - `kind`（`factor | strategy`，自动判定，可被对话改写）
  - `title / explanation / question`
  - `messages[]`（含 `attachments[]`：`object_key / filename / kind[text|image] / extracted_text`）
  - `code`（因子 bundle 或策略源码）
  - `code_test_result`（`exit_code / stderr / duration_ms`）
  - `backtest_plan`（Agent 建议：默认周期/区间 + rationale）+ 用户覆盖
  - `backtest_results[]`（每次 NT 回测可追溯，含 `backtest_hash`）
  - `paper_binding`（`account_id / published_at`）
  - `content_hash / versions[]`

## 4. 自然语言会话（`pi` Agent，非交互）

- **底层支撑**：复用现有可注入 Runner 体系，NL 会话由 **`pi` Agent 非交互模式**驱动。平台**只复用系统安装的 `pi` 二进制**，**不改动 `pi` 自身的全局配置**。
  - 调用形态：`pi -p --no-session --mode text <prompt>`（与现有 `_pi_complete` 一致）。
  - **项目独立基座模型配置（关键隔离点）**：`pi` 本次运行加载的是**当前项目的基座模型配置**，通过 CLI 参数注入：
    `pi -p --no-session --mode text --provider <PROVIDER> --model <MODEL> [--api-key <KEY>] <prompt>`
    - 配置来源：项目 `.env`（如 `PI_PROVIDER` / `PI_MODEL`，可选 `PI_API_KEY`）或本项目独立的基座模型配置项。
    - **隔离语义**：模型/provider 只对本项目的本次调用生效，**绝不写入 `pi` 自身的配置**；因此在本项目改基座模型，不会影响其他项目或其他用户使用 `pi` 时的基座模型。
    - 未配 `--provider`/`--model` 时，回退到 `pi` 默认（`pi auth` / 用户已装配置），但优先取项目配置。
  - **兜底**：当 `pi` 不可用、或项目未配置基座模型时，降级到 `DEEPSEEK_API_KEY` → `ZHIPU_API_KEY`（沿用现有 `default_runner` 的可用性探测）。计划会调整选择顺序，让 `pi` 成为**默认首选**，深水区仍以供应商 HTTP 直连兜底。
- **非交互要点**：单请求/无 session 状态；每次对话轮次以一个完整 prompt（历史 + 附件抽取文本 + 系统提示）调用 `pi`，返回结构化 JSON（`title / explanation / question / code / instrument_ids / frequency / backtest_plan / ready`）。
- **附件语义**：
  - 文本（PDF/DOCX/TXT/CSV）→ 抽取纯文本，注入 prompt。
  - 图片（研报截图、回测图、图表）→ 走视觉/OCR：优先交给 `pi`/多模态模型「看图理解」，否则 OCR 抽取文字保底，同样注入 prompt。
- **多轮细化**：对话为「逐步细化策略」的主通道；Agent 每次返回 `question` 追问（空串=已明确），`ready=true` 才进入代码阶段。

## 5. 各阶段细化

### 5.1 新建研究（工作台）
- 单入口：只选「市场」（A股 / 商品期货），进入**左对话 / 右工件**的工作台。
- 左=对话线程：多轮 `pi` Agent + 附件上传（文本 + 图片）。
- 右=实时工件面板：标题/说明/标的/周期/目标（自动判定因子或策略）/阶段进度条。
- 旧的详细表单（universeRef / 时钟 / 交易所范围 / 合约选择）折叠为「高级设置」，Agent 可代填，用户可手动覆盖（尊重既有正式研究数据）。
- 一键创建路径：粘贴论文/研报文本或上传附件 → Agent 抽取并为因子/策略建模。

### 5.2 生成代码
- 因子形态：沿用 `extractSpec → genCode`（模型/train/infer 三件套 + bundle）。
- 策略形态：沿用 G19 prompt（`Strategy` 子类 + 安全扫描）。
- 产物统一入 `Research.code`。

### 5.3 代码正确性测试（新增，硬分界于回测）
- **目标：找一段适用数据（极小 fixture），能跑通即可**——不求好坏、不测逻辑断言。
- 复用因子侧现有**沙箱试运行**能力（`smokeFiles` / factor-build「3 试运行」）：
  - 编译 + 实例化 + 用极小 fixture（几根 bar / 几行输入）端到端跑一遍；
  - 不崩、不超时视为通过；返回 `exit_code / stderr / duration_ms`。
- **门禁**：测试通过才解锁「去回测」。测试=能跑，回测=测好坏。

### 5.4 回测（复用 NT，只做可视化）
- **不重构回测引擎**：直接复用现有 `StrategyBacktestService` / `run_strategy_backtest`（NautilusTrader `BacktestEngine` + 中国市场费用/涨跌停口径）。
- 页面：选研究 → 展示 Agent 建议（`backtest_plan` 默认周期/区间 + rationale）→ 用户可改周期/起止 → 「运行回测」→ NT 结果。
- **可视化**：复用现有结果组件（净值 sparkline + 总收益/夏普/最大回撤/成交次数 + 成交/持仓列表 + `net_of_fees` 口径）。把 `strategy-chat` 右侧回测面板升格为独立「回测」页。
- 历史：每次运行存 `backtest_results[]`（含 `backtest_hash`），可对比/追溯。

### 5.5 发布仿真（Paper）
- 复用现有 paper 账户/监控（orders/fills/positions/equity）。
- **发布**：从某条回测结果 → 「发布到仿真盘」→ 建/绑仿真账户 → 记录 `paper_binding` → 跳转仿真页直播。
- 门禁：`无约束违规 + 用户确认` 即放行（不强硬阻断）。

### 5.6 保存 / 沉淀
- 实时落库 + 显式「保存 / 存版本」打点；`content_hash` 快照可在任意阶段产生，用于回滚与分享。

## 6. 合并 / 拆解 / 移除

| 动作 | 对象 |
|---|---|
| **合并** | `新建研究`+`新建研究任务`+`新建任务` → 单「新建研究」 |
| **合并** | `PaperPipeline`+`ResearchJobForm` → 一份「NL 优先 + 高级设置可折叠」创建 |
| **合并** | 因子回测 `BacktestLab` + 策略回测 → 统一进「回测」页（策略回测为规范） |
| **拆解** | 研究任务详情页（简报/因子构建/实验/验证/晋升/谱系）→ 并入「研究」详情的阶段步骤；正式研究层（审计/合规）折叠为深水区 |
| **拆除导航** | `策略`、`策略对话`、`执行`；环境选择器保留，实盘作为环境维度 |

## 7. 数据模型改动（尽量小、可迁移）

- **`Research`（升级自 `StrategyDraftModel`）**：新增 `kind`、`code_test_result`、`backtest_results[]`、`paper_binding`、`versions[]`；状态机扩展为 `CREATING → READY → CODE_TESTED → BACKTESTED → PAPER_LINKED`（任意态可 SAVED）。
- **附件**：`StrategyMessageModel` 增 `attachments`(JSON)，或新增 `research_attachments` 表。
- **因子侧**：`FactorBuildSpec` / `FactorCodeBundle` 迁移到同一「研究」容器（`kind=factor`），UI 外壳统一。
- **不做**：不动 NT 引擎、不动 `BacktestEngine` 装配；`run_strategy_backtest` 保持原样。

---

## 8. 后端/Agent 改动

- Runner：`pi` 为默认首选（非交互 `pi -p --no-session --mode text`），**模型/provider 通过 CLI 参数取自项目基座模型配置（如 `PI_PROVIDER`/`PI_MODEL`），只对本项目调用生效，不写入 `pi` 自身配置**（改本项目基座模型绝不污染其他项目使用 pi 的模型）；DeepSeek/Zhipu 兜底、模型仍由各自项目 `DEEPSEEK_MODEL` / zhipu 配置决定。
- `POST /strategy-drafts/{id}:code-test`：沙箱「跑通」门禁（复用因子 sandbox）。
- `POST /research/{id}:publish-paper`：回测结果 → 建/绑仿真账户 → 记录绑定。
- 因子 `smokeFiles` 与策略 code-test 共用同一沙箱能力，返回结构对齐。
- 附件：上传 → MinIO + 文本抽取 + 图片视觉/OCR → 注入 prompt。

## 9. 前端 / UI 设计（美观、大方、有记忆点）

**按 `frontend-design` / `design-taste-frontend` skill 推进**，避免模板化默认（奶油底+衬线大字、近黑+酸性绿、报纸式密排等）。

- **subject 定位**：这是一个「每个结果都携带证据」的量化研究控制面。设计语言围绕**证据 / 可审计性 / 数字精度**展开。
- **设计原则（来自 skill）**：
  - 首页 hero = 一句话主张 + 关键数字，不用模板化渐变卡片。
  - 用**等宽数字表**承载数据（指标、净值、成交），让"精确"成为性格而非装饰。
  - 结构即信息：阶段步骤、证据提示条、口径声明要做真实内容，不做装饰性编号。
  - 移动了一处风险点：**签名元素**——一个贯穿全站、能记住的元素（如「证据导轨 / 阶段灯塔」），其余保持克制。
- **token 系统**：4–6 个具名色 + 展示/正文/数据三档字体 + 清晰的间距刻度 + 克制动效（尊重 reduced-motion、键盘焦点、移动端）。
- **四页布局要点**：
  - **概览**：研究列表 + 阶段进度条 + 关键计数；空态是邀请，错误态讲清楚原因与修复。
  - **新建研究**：左对话 / 右工件，附件拖拽位清晰，阶段进度可视化。
  - **回测**：左「研究 + 建议 + 参数」，右「结果可视化 + 口径声明 + 历史」。
  - **仿真**：账户卡片 + 订单/成交/持仓/净值分栏。
- 落地时：构思 token 系统 → 与需求对齐（去模板化自查）→ 按 token 写 CSS（注意选择器优先级，避免 `.section` 与元素选择器互相覆盖）→ 截图自查 → 剪掉多余修饰（Chanel 法则）。

## 10. 实施顺序（灰度）

| Phase | 内容 | 风险 |
|---|---|---|
| **P1** | 导航收敛为 4 项；单「新建研究」；创建页 NL 优先 + 高级折叠 | 低 |
| **P2** | 统一「研究」容器 + 生命周期（任意态可保存快照）；左对话/右工件 | 中 |
| **P3** | 附件（文本 + 图片）：MinIO + 抽取 + 视觉/OCR → 喂 Agent | 中 |
| **P4** | 代码正确性测试（沙箱「跑通」门禁）；策略侧复用因子 sandbox | 中 |
| **P5** | 「回测」独立页：复用 NT + 现有可视化 + `backtest_results[]` 历史 | 低 |
| **P6** | 仿真发布：回测 → 账户绑定 → 直播监控 | 低 |
| **P7** | 因子流水线对齐 + 研究详情拆解；正式研究层折叠为审计深水区 | 中高 |

## 11. 待拍板项

1. **保存粒度**：任意步快照 = 每步盖章不可变版本，还是研究实时落库 + 显式「保存/版本」打点？（倾向后者）
2. **发布门禁**：仅用户确认，还是「无约束/T+1 违规 + 用户确认」？（倾向后者，仍不强硬）
3. **图片附件深度**：OCR 抽文字保底即可，还是要模型「看图理解」做推断？（倾向两者，OCR 保底）
4. **旧正式研究（时钟/交易所/合约）**：保留为「高级设置」并由 Agent 代填，还是未来迁移掉？（倾向保留）
5. **项目基座模型未配置时**：当前 `pi` 已安装但未认证 provider，项目 `.env` 也未设 `PI_PROVIDER`/`PI_MODEL`；是否在「新建研究」页对不可用状态给出可操作提示（去项目配置基座模型 / 用兜底供应商）？

## 12. 关键依赖与风险

- **`pi` 依赖用户环境与项目基座模型配置**：模型通过 CLI 参数从**项目配置**注入、`pi` 自身配置不被修改；若项目未配 provider/model 或 `pi` 不可用，需确保兜底链路（DeepSeek/Zhipu）可用，避免单点。
- **附件图片处理成本**：多模态/OCR 需供应商支持，做好失败降级。
- **因子流水线迁移**：`factor-build` 涉及训练/推理/验证（较重），迁移到大容器时需保住既有数据与晋升链路不变。
- **统一 payload**：因子与策略回测结果结构不同，UI 需做归一化适配分栏，避免破坏现有可视化。
