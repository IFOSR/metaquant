# 导入回测结果作为 Agent 上下文设计

## 目标

在策略对话输入区支持选择当前策略草稿的一次历史回测，并在发送下一条消息时由后端安全解析该回测，将其作为结构化上下文提供给 Agent，帮助 Agent 分析结果并提出优化方向。

## 范围

- 一次消息最多导入一条历史回测。
- 只能选择当前策略草稿已经成功记录的回测。
- 导入的是回测引用，不是用户可编辑的完整 JSON。
- Agent 只基于回测结果提出分析和优化建议，不自动修改或执行策略。
- 没有导入回测时，现有策略对话行为保持不变。

## 现状与复用

- `StrategyDraft` 已通过 `backtest_results` 返回历史回测摘要，包括 `backtest_hash`、日期区间、周期、指标和执行时间。
- 后端已有 `GET /strategy-drafts/{draft_id}/backtests/{backtest_hash}`，可按 hash 验证归属并重放完整回测。
- 当前对话消息支持文本和图片附件，但没有结构化回测引用字段。
- Agent 上下文由 `strategy_generation/api.py` 中的历史消息重建逻辑组成。

## 方案

采用“前端选择 hash，后端验证并重放”的方案：

1. 前端从当前 `StrategyDraft.backtestResults` 渲染历史回测选择器。
2. 用户选择一条记录，输入框区域显示引用卡片；用户可以取消选择或改选另一条。
3. 发送消息时请求体增加可选 `backtest_hash`。
4. 后端验证 hash 存在于当前草稿的历史记录中，并确认当前用户具备该草稿的读取和写入权限。
5. 后端重用已有回测重放逻辑取得完整结果，生成紧凑、稳定的上下文文本。
6. Agent 收到的用户内容包含原始消息和明确标记的回测上下文。
7. 持久化消息时记录回测引用元数据，使历史消息可追溯并能在重新打开对话时显示引用。

不采用前端直接发送完整回测 JSON：这会扩大请求体、允许客户端篡改结果，也无法保证 Agent 分析的结果确实属于当前草稿。

## 数据流

```text
StrategyDraft.backtestResults
        │
        ▼
前端单选历史回测 ── selected backtest_hash ──► POST strategy message
                                                   │
                                                   ▼
                                        校验当前草稿历史记录
                                                   │
                                                   ▼
                                           重放完整回测结果
                                                   │
                                                   ▼
                                   组装 Agent backtest context
                                                   │
                                                   ▼
                                           run_turn(...)
                                                   │
                                                   ▼
                               持久化用户消息 + 回测引用 + Agent 回复
```

## 前端设计

### 入口

在策略对话输入框的“添加附件”附近增加“导入回测结果”按钮。以下状态禁用入口：

- 当前没有草稿。
- 当前草稿没有历史回测。
- 草稿已冻结且当前界面不允许继续发送消息。

### 选择器

使用弹层或下拉面板展示当前草稿的历史回测，按最新执行时间倒序。每项至少显示：

- 执行时间
- 回测区间
- 执行周期
- 总收益
- Sharpe
- 最大回撤
- 成交数

选中后显示引用卡片，包含日期、周期和结果指纹；点击移除后恢复未选择状态。

### 消息与历史

- 发送期间保留用户原始文本和选中的回测引用，成功发送后清空选择。
- Agent 回复消息中不重复渲染完整回测 JSON。
- 重新加载草稿时，历史用户消息显示其关联的回测引用。
- 若历史消息是旧格式，没有回测引用，按现有方式渲染。

## 后端协议

扩展 `PostStrategyMessageCommand`：

```json
{
  "message": "分析这次回测为什么频繁止损，并给出优化建议",
  "attachments": [],
  "backtest_hash": "..."
}
```

`backtest_hash` 为可选字符串，空值等同于未导入回测。后端不得接受客户端提交的完整回测结果作为可信上下文。

消息持久化沿用现有 JSON 附件/元数据机制，增加可识别的回测引用结构，至少包含：

```json
{
  "kind": "backtest",
  "backtest_hash": "...",
  "name": "回测结果 2026-03-07 至 2026-09-07",
  "extracted_text": ""
}
```

回测引用不应被当作普通文本附件注入；历史重建时由后端按 hash 重新获得上下文，或在回测不可重放时返回明确的不可用状态。

## Agent 上下文格式

后端生成带边界的文本块，避免 Agent 将回测事实误认为用户刚刚提出的新策略规则：

```text
[导入的历史回测结果]
来源：当前策略草稿的一次已记录回测
结果指纹：...
标的：...
市场：...
周期：...
回测区间：...
费用口径：...
绩效指标：
- 总收益：...
- Sharpe：...
- 最大回撤：...
- 成交数：...
- 总手续费：...
持仓回合：
...
逐笔成交：
...
净值曲线采样：
...
[回测结果结束]
```

上下文应优先包含指标、费用、逐笔成交和持仓回合；净值曲线只发送有序采样点，限制长度，避免六个月分钟数据耗尽 Agent 上下文。原始用户消息必须保留在上下文中，并放在回测上下文之前或之后使用明确分隔符。

## 校验与错误处理

- hash 不存在于当前草稿历史：返回 `404` 或统一问题响应，不调用 Agent。
- 回测记录存在但当前草稿不满足重放条件：返回可操作错误，不调用 Agent。
- 回测重放失败：保留输入框内容和选择状态，显示失败原因，不写入一条假成功消息。
- 发送不带 hash：继续走现有路径。
- 发送中重复点击：沿用现有 `busy` 状态，不能重复提交。
- 回测 hash 只按当前草稿范围解析，不能跨草稿引用。

## 测试设计

### 后端

- schema 接受可选 `backtest_hash`，拒绝未知字段。
- 合法 hash 能被当前草稿验证并生成 Agent 回测上下文。
- 不属于当前草稿的 hash 被拒绝，且 Agent runner 不被调用。
- 不带 hash 的消息保持现有行为。
- 回测重放失败返回错误，不持久化假消息。
- 历史消息能保留并返回回测引用元数据。
- 上下文包含指标、交易方向化动作、持仓回合和结果指纹。

### 前端

- 历史回测列表正确渲染并按时间倒序。
- 单选行为生效，重新选择会替换旧引用。
- 移除引用后请求不再携带 `backtest_hash`。
- 发送请求携带选中的 hash，成功后清空选择。
- 旧消息和无回测历史时保持兼容。

## 非目标

- 本功能不支持多选回测横向比较。
- 本功能不新增永久回测结果表。
- 本功能不让 Agent 直接运行新的回测。
- 本功能不在当前阶段把净值曲线改造成 OHLC K 线数据。
